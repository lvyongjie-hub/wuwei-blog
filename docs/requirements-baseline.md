- 基线版本：`v1.0`
- 冻结日期：2026-07-27

## 1. 项目目标

“五味书房”是一个以长期个人品牌建设为首要目标、以个人知识沉淀为次要目标的开源个人网站。

网站面向技术同行、潜在合作伙伴和少量招聘者，使访客能够通过真实项目和持续写作形成以下认知：

> 五味是一位能够把复杂问题做成可靠项目，并持续思考、验证和记录过程的嵌入式开发者。

核心专业主线：

- 嵌入式系统与固件工程。
- MCU、RTOS、驱动协议和系统可靠性。
- 真实工程项目、问题排查和验证方法。

第二专业支柱：

- 边缘 AI。
- TinyML 与端侧模型部署。
- AI 辅助固件开发。
- 智能硬件及其工程实践。

AI 内容必须与工程实践产生连接，不发布泛化的 AI 新闻转载。

## 2. 品牌表达

### 2.1 名称

- 中文站名：**五味书房**
- 英文站名：**Wuwei’s Digital Study**
- 公开署名：**五味**

### 2.2 核心宣言

> 我喜欢把复杂的系统拆开，慢慢做成可靠的东西；也把一路上的试错、学习和灵感，留在这间数字书房里。

### 2.3 表达语气

- 清晰、克制、诚实。
- 像一位认真做工程、喜欢思考，也愿意分享过程的人。
- 技术内容严谨具体，不回避失败、限制和未完成验证。
- 随笔允许更自由、更有温度，但不稀释专业主线。
- 不使用夸张营销语言，不把编译成功描述成硬件验证成功。

### 2.4 身份与隐私

- 正文署名、页面元数据和社交预览统一使用“五味”。
- 普通页面不公开真实姓名。
- 首版不公开托管包含真实姓名的 PDF 简历。
- 关于页面提供匿名化职业经历时间线。
- 访客可以通过邮件索取完整简历，由五味主动发送。

## 3. 内容战略

网站长期内容比例目标：

- 40% 项目档案。
- 30% 工程深度文章。
- 20% 嵌入式与 AI 实验记录。
- 10% 读书与生活随笔。

内容公开原则：

- 以个人项目、开源项目和可复现实验为主体。
- 工作项目只发布脱敏案例。
- 脱敏案例可以展示问题、工程决策、验证方法和结果。
- 不公开客户信息、密钥、敏感指标、受限源代码或生产资料。
- 不修改或绕过硬件安全条件来制造演示结果。

语言策略：

- 中文为主。
- 关键项目和代表文章提供英文标题、摘要及技术关键词。
- 首版不制作全文双语内容。

## 4. 首版内容范围

首版以完成网站结构、视觉系统和内容工具链为主，不为了填充页面创作虚构内容。

首版包含：

- 一个真实旗舰项目档案。
- 完整首页、书房、项目档案、随笔、关于、搜索和隐私页面。
- 空知识库、实验记录和随笔栏目使用克制的“正在整理”状态。
- 后续写作所需的 Markdown/MDX 内容模板。

首版不包含：

- 知识库正式文章。
- 实验文章。
- 生活或读书随笔。
- 虚构示例文章。

### 4.1 首发旗舰项目

项目名称：**STM32F407 四通道工业数据记录终端**。

项目来源：`E:\ztest\stm32f407_data_terminal`。

案例可呈现：

- STM32F407 与四通道 ADC 采集。
- FreeRTOS 任务划分与共享资源所有权。
- LVGL 触摸界面。
- 内部 Flash 配置、版本与 CRC 校验。
- RTC、SD 卡和 CSV 数据日志。
- 告警及回差逻辑。
- Bootloader、应用分区和固件迁移。
- 工业模拟量输入、模拟前端和后续可靠性规划。

发布边界：

- 项目状态为“进行中”。
- 只陈述实际完成的软件实现和静态/编译验证。
- 明确列出尚未完成的实体板联调、校准及长期运行测试。
- 博客仓库不复制固件源码、厂商 SDK、生成物或第三方硬件资料。
- 首版不显示项目源码入口。
- 项目仓库许可证完成核查前，不把“源码可见”等同于“开源许可”。
- 当前没有真实项目截图；首版使用统一工程架构封面，不生成虚构硬件照片。
- 页面预留真实硬件照片和界面截图区域，后续补充。

- 书房 `STUDY`
- 项目档案 `PROJECTS`

实验记录是独立内容类型，但不进入一级导航。

## 6. 首页需求

第一屏包含：

- 五味书票标识。
- 核心宣言。
- 当前专业方向的简短说明。
- “查看项目档案”主要入口。
- “进入数字书房”次要入口。

第一屏之后的顺序：

1. 精选项目。
2. 代表文章。
3. 当前研究方向。
4. 最近随笔。
5. 简短个人介绍。

首版没有文章时，代表文章和随笔区域使用“正在整理”状态，不展示假数据。

首页增加小型“此刻”模块：

- 正在研究。
- 正在构建。
- 最近在读。

“此刻”不单独设置一级页面。

## 7. 数字书房

书房采用类似语雀的知识组织方式：

> 知识库（一本书）→ 章节目录树 → 具体文章

书房首页：

- 使用知识库封面卡片。
- 显示标题、简介、主题色、文章数量、整理状态和最近更新时间。
- 不使用访客阅读进度。

知识库整理状态：

- 构思中。
- 编写中。
- 已成体系。

知识库文章桌面布局：

- 左侧为可折叠章节树。
- 中间为约 760px 的正文区。
- 右侧为当前文章目录。
- 移动端将两侧内容收进抽屉，只保留正文。

成体系的内容进入知识库；零散内容先保存在实验记录或随笔中，成熟后再编入知识库。

计划中的首批知识库主题：

- 《嵌入式系统可靠性实践》。
- 《端侧 AI 实验手册》。

首版只保留知识库结构和空状态，不录入正式文章。

## 8. 项目档案

项目采用两级结构：

- 重点项目：完整工程案例。
- 小型项目：简洁档案卡。

重点案例建议字段：

- 项目背景与目标。
- 个人职责。
- 系统与资源约束。
- 架构和模块划分。
- 关键技术决策。
- 问题排查过程。
- 验证方法与实际结果。
- 未验证项和风险。
- 复盘与后续计划。
- 可选仓库、演示或实物资料入口。

项目状态：

- 探索中。
- 进行中。
- 已发布。
- 已归档。

项目列表：

- 使用编辑式档案卡片。
- 支持年份、状态和技术标签筛选。
- 重点项目置顶。
- 小项目按最近更新时间排列。

项目不强制提供在线演示。无法演示或代码不可公开时，明确标注“仅展示案例”或“代码未公开”。

## 9. 随笔与实验记录

随笔支持两种形态：

- 短随笔：在时间流中完整显示，并保留独立永久链接。
- 长随笔：列表显示摘要，点击进入完整页面。

随笔按时间组织，不建立复杂知识树。

实验记录是独立内容类型，并遵循以下成长路径：

> 灵感 → 实验记录 → 项目档案或知识库章节

## 10. 视觉设计系统

核心视觉母题：**工程师的数字书桌**。

设计原则：

- 现代编辑式布局。
- 克制使用书页、索引卡、工程图、档案夹和手写批注元素。
- 少量加入电路走线和波形细节。
- 不制作木桌、真实书架等重拟物界面。
- 个人风格服务于内容层级，不影响阅读。

基础配色：

| 用途       | 色值      |
| ---------- | --------- |
| 暖米白背景 | `#F3EFE6` |
| 墨黑正文   | `#25241F` |
| 松针绿主色 | `#315747` |
| 旧铜色强调 | `#B17A3D` |
| 灰绿色辅助 | `#7A8178` |

字体：

- 中文标题：思源宋体 / Noto Serif SC。
- 正文：思源黑体 / Noto Sans SC。
- 代码与技术元数据：JetBrains Mono。
- 手写字体只用于极少量批注。
- 字体尽量自托管，不依赖外部字体 CDN。

标识：

- 首页不使用大型真人照片。
- 以“五味”两个汉字制作方形书票或印章。
- 在印记中隐藏极细的电路走线或波形细节。
- 真人头像只允许在关于页面小范围出现。

主题：

- 默认跟随操作系统明暗主题。
- 用户可以手动切换，选择需要持久保存。
- 浅色主题表现白昼书房。
- 深色主题表现夜间书桌。
- 深色主题使用暖黑和低饱和绿色，不使用霓虹科技风。

动效：

- 页面淡入。
- 卡片轻微抬起。
- 目录定位过渡。
- 阅读进度反馈。
- 少量电路信号或波形动画。
- 不使用粒子背景、强视差、自动音效或持续大型动画。

首版不实现专注阅读模式。

## 11. 媒体与封面

- 项目与文章封面采用统一设计系统。
- 优先使用文字封面、工程示意图、电路局部、波形和真实项目照片。
- 不使用无关图库照片。
- 不依赖风格不一致的随机 AI 配图。
- 小型图片和 SVG 可以进入仓库。
- 大型原始照片、视频和数据集使用对象存储，页面引用压缩后的 WebP/AVIF。
- 不使用不稳定的第三方热链。
- 每篇文章和项目自动生成统一 OG 社交预览图。

## 12. 技术架构

首版采用定制开发，不直接套用完整开源博客主题。

计划技术栈：

- Astro。
- Tailwind CSS。
- TypeScript。
- Astro Content Collections。
- Markdown / MDX。
- Pagefind 静态搜索。
- Mermaid 图表。
- 数学公式渲染。
- Giscus + GitHub Discussions。
- GitHub Actions。
- Cloudflare Pages。

实现原则：

- 尽量静态生成。
- 尽量减少客户端 JavaScript。
- 内容在无 JavaScript 时仍应可以阅读。
- 不为首版引入不必要的数据库或服务端运行时。

## 13. 写作与内容管理

主流程：**本地 Markdown/MDX + Git**。

- 文章、知识库目录、项目档案和实验记录均可版本管理。
- 公开仓库只保存已确定公开的内容。
- 未完成文章、私人随笔和敏感资料放入独立私有仓库或本地笔记库。
- `draft: true` 不能作为公开仓库中的隐私保护措施。
- 在线编辑入口以后按需要增加，首版不实现。

技术文章需要支持：

- 带文件名的代码块。
- 行高亮。
- 一键复制。
- Mermaid。
- 数学公式。
- 脚注。
- 提示块。
- 表格与图片说明。
- 可折叠细节。
- 外部仓库引用卡片。

引用规范：

- 论文、标准、芯片手册、官方文档和外部代码必须保留来源。
- 正文使用脚注，文末生成参考资料区。
- 记录适用版本或访问日期。

文章版本信息：

- 首次发布日期。
- 最后更新时间。
- 适用 MCU、SDK、RTOS 或模型版本。
- 重大修改保留简短修订记录。

内容生命周期：

- 仍适用。
- 部分过时。
- 已归档。

过时内容原则上不直接删除，而是在顶部说明影响版本和替代内容；涉及安全风险或明显错误时撤下正文并保留说明。

GitHub 内容入口：

## 17. 部署与发布流程

- GitHub 托管源码。
- Cloudflare Pages 自动构建和发布。
- `main` 分支对应正式网站。
- 功能和文章通过独立分支与 Pull Request 提交。

## 18. 自动化检查

GitHub Actions 至少执行：

- 格式检查。
- TypeScript 类型检查。
- Astro 正式构建。
- Markdown 内外部链接检查。
- 内容字段和 frontmatter 校验。

## 19. 性能、可访问性与兼容性

- 移动端优先。
- 支持当前主流版本的 Chrome、Edge、Firefox 和 Safari。
- 支持 Android 与 iOS 主流浏览器。
- 不支持 Internet Explorer。
- 增强功能不可用时，正文和导航仍必须正常工作。
- 支持键盘导航。
- 支持 `prefers-reduced-motion`。
- 文字和交互对比度满足基本可访问性要求。
- Lighthouse 各核心类别以 90+ 为目标。
- 控制首屏资源和客户端 JavaScript 体积。

## 20. 访问分析与隐私

- 使用 Cloudflare Web Analytics。
- 只查看访问量、热门页面、来源和基础性能数据。
- 不设置广告追踪。
- 不建立用户画像。
- 不引入不必要的 Cookie 弹窗。
- `/privacy/` 说明 Cloudflare Analytics、Giscus、外部链接和服务器日志。
- 网站不收集联系表单数据。

- 明暗主题、响应式导航和移动端布局可用。
- 语雀式知识库结构与三栏阅读布局已经搭建。
- Markdown/MDX 内容模型和模板可供后续写作。
- Pagefind、RSS、OG 图片和基础 SEO 可用。
